Building a Consistent Website

1. Overview

Modern websites rarely consist of isolated pages designed independently. Instead, they use a shared structure and a consistent visual system. This makes the website easier to maintain, easier to expand, and more predictable for users.

Week 3 introduces two fundamental ideas:

  • Template inheritance: define the common HTML structure once and reuse it across pages.
  • Reusable CSS: define the visual language of the website once and apply it consistently.

The main principle

Instead of repeating the same header, navigation bar, footer, colors, spacing, and layout rules on every page, we define them once and reuse them throughout the website.

This follows an important software-engineering principle: avoid unnecessary repetition.

2. Jinja Template Inheritance

A Flask website can use Jinja template inheritance to separate shared structure from page-specific content.

The shared structure normally lives inside base.html. Individual pages then inherit from that template.

Base template

A base template may contain the common document structure:

  • HTML document structure
  • Page metadata
  • Website header
  • Main navigation
  • Stylesheet connection
  • Main content area
  • Footer
<!DOCTYPE html>
<html lang="en">

<head>
    <title>
        {% raw %}{% block title %}My Portfolio{% endblock %}{% endraw %}
    </title>
</head>

<body>

    <header>
        Shared website header
    </header>

    <main>
        {% raw %}{% block content %}{% endblock %}{% endraw %}
    </main>

    <footer>
        Shared footer
    </footer>

</body>

</html>

Child template

A child template only needs to provide the content that is different. 

{% raw %}{% extends "base.html" %}

{% block title %}
Week 3
{% endblock %}

{% block content %}

<h1>My Week 3 Page</h1>

{% endblock %}{% endraw %}

Why template inheritance matters

Imagine a website with twenty pages. If the navigation bar were copied into every file, adding one new menu item would require editing twenty separate documents.

With template inheritance, the navigation is changed once in base.html, and every child page receives the update.

3. What CSS Does

HTML defines the meaning and structure of content. CSS controls how that content is presented.

CSS can control:

  • Colors
  • Typography
  • Spacing
  • Borders
  • Backgrounds
  • Dimensions
  • Alignment
  • Layouts
  • Responsive behavior
  • Hover and focus states
  • Transitions and visual effects

CSS rule anatomy

selector {
    property: value;
}

For example: 

h1 {
    color: #0b1f3a;
    font-size: 2rem;
}

Here, h1 is the selector, color and font-size are properties, and their assigned settings are values.

4. CSS Variables and Design Tokens

CSS custom properties, commonly called CSS variables, allow important values to be defined once and reused throughout the stylesheet.

They are often placed inside :root so they are available throughout the page. 

:root {
    --color-primary: #0b1f3a;
    --color-secondary: #1e4d7b;
    --color-background: #ffffff;

    --space-small: 0.75rem;
    --space-medium: 1rem;
    --space-large: 1.5rem;

    --radius: 12px;
}

The variables can then be reused: 

header {
    background: var(--color-primary);
}

section {
    padding: var(--space-large);
    border-radius: var(--radius);
}

Why use design tokens?

Design tokens represent the reusable visual decisions of a website. Instead of thinking only about individual CSS rules, the developer defines a small design system.

Token Category Example Purpose
Color --color-primary Main brand or interface color
Spacing --space-lg Maintains consistent spacing
Typography --font-sans Controls the main typeface
Radius --radius Creates consistent rounded corners
Shadow --shadow-soft Creates consistent visual depth

5. Modern CSS Layout

Two of the most important modern CSS layout systems are Flexbox and CSS Grid.

Flexbox

Flexbox is designed primarily for arranging elements in one dimension: either a row or a column.

It is particularly useful for:

  • Navigation menus
  • Button groups
  • Horizontal alignment
  • Vertical centering
  • Distributing space between elements
nav ul {
    display: flex;
    justify-content: center;
    align-items: center;
    gap: 1rem;
}

CSS Grid

CSS Grid is a two-dimensional layout system. It controls rows and columns at the same time.

It works especially well for:

  • Card galleries
  • Dashboards
  • Page sections
  • Responsive content collections
.weekly-list {
    display: grid;

    grid-template-columns:
        repeat(
            auto-fit,
            minmax(240px, 1fr)
        );

    gap: 1rem;
}

6. Responsive Web Design

Responsive design allows one website to adapt to different viewport sizes rather than requiring separate desktop and mobile websites.

A responsive layout should preserve readability and usability on:

  • Phones
  • Tablets
  • Laptops
  • Desktop monitors

Media queries

Media queries allow CSS rules to apply only when a particular condition is true. 

@media (min-width: 641px) {

    main {
        width: min(100% - 2rem, 1100px);
    }

}

This technique allows the layout to change when the available screen space changes.

Mobile-first design

In a mobile-first approach, the default CSS is designed for smaller screens. Media queries then progressively enhance the design for larger screens. 

/* Phone first */

.card {
    padding: 1rem;
}

/* Larger screens */

@media (min-width: 768px) {

    .card {
        padding: 2rem;
    }

}

7. Flexbox vs. Grid

Feature Flexbox Grid
Dimensions Primarily one-dimensional Two-dimensional
Main structure Row or column Rows and columns
Typical use Navigation, controls, alignment Page layouts and galleries
Alignment Excellent Excellent
Responsive layouts Very useful Very useful

9. Recommended Development Workflow

  1. Build semantic HTML. Structure the information logically before worrying about appearance.
  2. Extract shared structure. Move repeated page elements into base.html.
  3. Create design tokens. Define reusable colors, spacing, typography, radii, and shadows.
  4. Style shared elements. Establish consistent headings, navigation, sections, links, tables, and components.
  5. Apply modern layout tools. Use Flexbox and Grid according to the structure of the content.
  6. Make the layout responsive. Test narrow and wide viewports and introduce media queries where needed.
  7. Test every page. Verify that shared styles and navigation still behave correctly.
  8. Deploy and verify. Push the final version and check the live website.

10. Common CSS Mistakes

Repeating the same values everywhere

Repeating colors and spacing values makes future changes harder. Design tokens can centralize these decisions.

Using fixed widths everywhere

Large fixed widths can cause horizontal overflow on smaller screens. Flexible units, maximum widths, Grid, Flexbox, and media queries provide more adaptable layouts.

Ignoring narrow screens

A design that works only on a desktop is incomplete. The browser should be tested at multiple viewport widths.

Overusing CSS

More CSS does not automatically mean better design. Reusable rules, clear selectors, and a consistent design system usually produce more maintainable results.

11. Key Takeaways

  • Shared structures should be defined once.
  • Jinja inheritance prevents unnecessary HTML repetition.
  • One stylesheet can provide a consistent visual identity.
  • CSS variables make design decisions reusable.
  • Flexbox is well suited to one-dimensional layouts.
  • Grid is well suited to two-dimensional layouts.
  • Media queries allow layouts to respond to viewport conditions.
  • Responsive design should preserve readability and usability.
  • A reusable design system makes future pages easier to build.
